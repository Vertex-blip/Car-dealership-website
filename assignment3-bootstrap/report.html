Objective and approach

Build once, adapt to every screen

The goal was to practice responsive web design with CSS media queries and Bootstrap's 12-column grid, then apply Bootstrap components and spacing utilities to a cohesive dealership mini-site. A separate project copy keeps the existing Assignment 1/2 website unchanged.

Step-by-step implementation

  1. Created the isolated assignment3-bootstrap/ project and linked eight task pages through a responsive shared navigation.
  2. Added mobile, tablet and desktop media-query breakpoints for typography and a three-card layout built with plain CSS.
  3. Replaced demonstration-section layouts with Bootstrap containers, rows and responsive columns; used Bootstrap spacing classes for gutters and padding.
  4. Added a collapsible navbar, grouped buttons, a nine-slide local-image carousel, responsive Bootstrap cards and a labeled, validated inquiry form.
  5. Reviewed semantic structure, image alternatives, contrast, visible keyboard focus and accessible names for interactive controls.
  6. Captured real browser views and source excerpts, then prepared this PDF and the LMS ZIP.

Part 2 · Bootstrap foundation

Tasks 3–4 · Grid and spacing utilities

grid-spacing.html demonstrates a two-column section using col-lg-6 and a three-column section using col-lg-4. Both start full-width on narrow phones, then use tablet and desktop breakpoints. Bootstrap container, row, and gutter classes align content consistently.

Spacing is expressed with Bootstrap utilities rather than custom layout margins and padding: examples include py-4, px-sm-2, g-md-4, and mt-lg-4. The utilities adjust at responsive breakpoints.

Forms and accessibility

Tasks 9–10 · Responsive and inclusive

The inquiry page uses responsive Bootstrap columns and labeled controls, including .form-control, an .input-group, radio choices and a checkbox. Required name/email fields use native validity checks with Bootstrap invalid-feedback states. The demonstration explicitly does not transmit or store entered data.

Accessibility checklist

  • Landmark elements, heading hierarchy, a skip link, and descriptive navigation names.
  • Associated form labels, a fieldset/legend for radio choices, status feedback, and visible keyboard focus.
  • Descriptive local image alternatives; sufficient contrast on dark navigation/footer surfaces; reduced-motion styling.
  • Carousel indicators and previous/next controls use descriptive accessible names; carousel does not move without user action.

Final reflection

This assignment showed how CSS media queries and Bootstrap can complement each other: explicit breakpoints are useful for a small custom card group and typography exercise, while Bootstrap grid, components and spacing utilities speed up consistent layouts across a multi-page site. Local images make the carousel dependable, and accessible labels, focus styles and user-controlled movement improve the experience beyond visual responsiveness.

Each teammate can explain a pair of pages and the decisions in their component. The form remains a front-end validation example only, so a production version would need a secure, consent-aware server endpoint. The published copy is isolated from the original Assignment 1/2 pages.
