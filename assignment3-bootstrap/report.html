01 · Responsive foundations

Objective

Build a self-contained, accessible dealership website that demonstrates all ten assignment requirements, uses CSS media queries for responsive behavior, and applies Bootstrap components and spacing utilities consistently without changing the existing Assignment 1/2 site.

CSS media queries, used with intention

The site keeps the original Assignment 1/2 website outside this folder. Assignment 3 has its own stylesheet, Bootstrap 5.3.3 links, local vehicle photographs, shared navbar, and linked learning pages.

Task 1 · Responsive typography

  1. Write actual dealership headings and paragraphs in typography-cards.html.
  2. Set smaller type at phone widths, then increase the same heading and paragraph at the 576px tablet and 992px desktop breakpoints.
  3. Resize or inspect the page at all three widths and compare the text scale and line wrapping.

02 · Bootstrap layout system

Tasks 3–4 · Grid and responsive spacing

Task 3 · Bootstrap grid

  1. Wrap both examples in Bootstrap containers and rows with consistent gutters.
  2. Use two col-lg-6 columns for the feature pair; they stack on phones and split at tablet widths.
  3. Use three col-lg-4 columns for the next set; col-sm-6 shows two columns at small screens.
  4. Resize the page to see the columns reflow without horizontal scrolling.

Task 4 · Bootstrap spacing utilities

  1. Replace intended layout spacing with Bootstrap utilities instead of custom margin/padding rules.
  2. Use breakpoint-specific examples such as px-sm-2, mt-lg-4, py-4, and responsive gutters.
  3. Check that spacing remains legible as the grid changes at phone, tablet, and desktop widths.

Grid and spacing utilities · visible content comes from grid-spacing.html.

06 · Accessible inquiry

Task 9 · Responsive Bootstrap form

  1. Lay out the form with responsive Bootstrap columns, including col-md-6 field pairs.
  2. Associate a visible label with every control; use form-control, form-select, and a budget input-group.
  3. Include an accessible radio fieldset, a labeled checkbox, and optional free-text details.
  4. Validate the required name and email fields; send invalid focus to the first invalid control and announce a result through a live status region.
  5. State clearly that this classroom demo does not transmit or store personal information.

The form's success state is only a local validity demonstration; there is no submission endpoint.

08 · Reflection

Final reflection

Building the site as one connected experience helped us see how responsive design depends on more than changing column counts. Bootstrap's grid and spacing utilities made the shared layouts consistent, while CSS media queries gave the typography and three-card exercise precise control at each breakpoint. Keeping navigation, accessible labels, local imagery, and the team contributions consistent across separate pages made the result easier to use and understand. We would carry that balance of reusable components, careful responsive testing, and clear ownership into our next project.
